## Model contract

| Profile | Boundary and traversal | Copying and collision semantics |
|---|---|---|
| `barricelli1954_reference` | Open finite interval; ascending source index; actual fixture initialization and horizon per figure | Taylor’s basic, symbiotic, exclusion and conditional routines are used directly. Basic self-retention uses its actual accumulation formula. Assisted copies refer to the original source and partners in the old row. Same-valued helpers do not extend historical chains. Exclusion uses a persistent-for-that-update `X` marker, stored as reserved integer 99999; it is distinct from empty 0. Conditional mutations use old-row nearest numerical neighbors and their positional distance. |
| `galloway_published` | Ring of 511 cells; ascending source index; old-row reads and sequential next-row writes | Three attempts maximum (initial plus two recursive calls), including equal-valued helpers and continuation after collisions. Every offset refers to the original source. Different next-row values collide: an occupied old-row target clears to 0; an empty old-row target receives signed `(u+v−1)`. Cleared targets are reusable by later sources. All reachable collision branches choose B: the `≤255×2` branch covers every remaining target through 510, making A unreachable. |
| `research` | Explicit configuration; current historical derivatives remain open, published-style derivatives remain rings | All changes are declared in `variant` and `modifications`. Implemented published-style collision rules are A, B, zero-erasure, spatial A:B halves, spatial A:B:A:B quarters and temporal A/B. A uses signed `(u+v)`. B uses signed `(u+v−1)`. Mixtures search the **whole old ring**, including across region boundaries. Temporal A is used at even update times, B at odd times; recurrence includes environment phase. |

In A/B formulas `u,v` are distances to nearest nonzero old-row values; sign is positive for equal signs, negative otherwise. Research halves require even width; quarters require a width divisible by four. Research profile `galloway_0` is implemented as an inspectable variant but was not an experimental treatment in the comparison. Source code, configurations and the run register specify exactly which variants were executed.

## Verification actually performed

All 22 historical examples match the upstream executable and instrumented engine across **16,694 fixture cells**. Figure 15 uses the corrected fixture, without patching output cells. Its historical-plate transcription first differs at time 8 (generation 9), and has 5,091 propagated cell differences across the full trajectory. This is not a count of independent hand-calculation mistakes.

The independently authored Galloway engine matches **1,597,386 cells** from unchanged, hash-verified Java-compatible numerical method bodies: six complete display runs plus six adversarial eight-update rows. Mechanically instrumented branch auditing confirms zero calls to A on the six display runs. Original Processing UI, Processing.js execution, the original RNG stream, and pixel identity with the published artwork were not validated. These limits are recorded in [results/galloway_validation/agreement.json](results/galloway_validation/agreement.json). Frozen Java oracle CSVs permit offline comparisons without distributing the sketch.

Every retained simulation contains exact `initial.csv`, streamed integer `trajectory.csv`, compressed `trajectory.npz`, configuration, statistics, native timing and provenance. Seed equality does not substitute for row equality. Provenance records the reference commit, exact source-file hashes, native binary hash, Python/NumPy/compiler versions and machine platform. This initially empty repository has no Git commit; per-run `repository_head` is null and content hashes supply version identity. Earlier orchestration source versions were hashed while under development; the final buildable source snapshot and complete current-engine replay provide the regeneration baseline. They do not claim to reconstruct every earlier orchestration edit.

Counters are operation-level: attempted copies, direct accepted outcomes (including equal-valued outcomes), collisions, newly produced outcomes, and erasures. “Newly produced” counts mutation calculations even when their value already occurred; first appearance of a numerical type is recorded separately. Optional events record copied source, target, depth, outcome, previous writer and ordered old-row helpers for small assay windows. They record local dependencies, not complete organism ancestry.

## Rendering and intervention contract

All visual forms derive from saved CSVs. [configs/palette.json](configs/palette.json) defines the shared dark/cyan research design and deterministic integer-to-HSV mapping. Empty 0 and exclusion `X` have explicit colors. The legacy Galloway palette has 36 explicit nonzero swatches and defaults to white for 0 and any other integer; the research renderer keeps out-of-palette integers visibly distinct from empty. Historical paper views use a numerical grid with underlined negatives. Colors encode **values**, never organism identities. The atlas supplies textual close-ups where colors are insufficient.

Each scientific PNG has source hashes, a caption and rendering metadata. Every curated print and animation has a numerical run, initial-state hash, configuration, palette hash and rendering recipe. Print pixels use integer nearest-neighbor scaling; animations progressively reveal existing rows and do not change the simulated dynamics. The atlas contains a selected browsable subset and links the complete native-run register. Its nearby worlds are explicit configuration interventions. Component edits, environment design, clearing eight spatial sites in saved row 256, initial layouts and aesthetic curation are externally imposed. Diagnostic control histories are explicitly synthetic and separately labeled.

Search proposal logs identify conversational Codex assistance, feedback hashes, hypotheses and wall intervals. There was no automated model integration, no per-cell model, no paid API call, and no CLIP or other embedding evaluation. Exact model-serving identifier and isolated model latency/token cost were not exposed by the conversational interface. The two feedback-to-submission intervals include other task work and are not model runtime measurements.
