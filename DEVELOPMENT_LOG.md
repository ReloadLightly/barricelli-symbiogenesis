# Implementation record

2026-10-10, first milestone. The VS Code/WSL repository initially had no tracked source, commits or uncommitted project work. The mission in `AGENTS.md` now guides scientific analysis, discovery comparisons and reproducible numerical art equally.

Taylor's public repository was cloned and its actual commit checked before implementation. Figure 7 was compiled and run first. GCC 11 lacked the upstream program's formatting facility, so a small formatting-only compatibility header was introduced; the numerical source remains unchanged. Representative historical trajectories preceded the orchestration and atlas.

The engine includes Taylor's functions with build-time observational insertions, alongside an independently authored Galloway behavior implementation. Tests and exact fixture comparisons cover the transitions encountered in this milestone. The source-level Java oracle was generated temporarily from privately retrieved, hash-verified method bodies; no unlicensed complete program is bundled.

Python orchestration saves integer initial states, stream-written CSV histories, compact NPZs, configuration, hashes and measurements. Native simulator memory is measured through `/usr/bin/time`; inherited pre-exec `getrusage` values are retained separately. Plotting and simulation are separate. GIF frames are streamed, limiting memory use on the small WSL machine.

Search proposals are recorded conversational decisions, rather than an automated API integration. Two rounds consume logged numerical feedback; every admissible run is retained. Replays use the stored decisions without model calls. Local neighbor exploration and environment variants expose compact configuration and collision-formula changes.

The temporal environment required phase-aware recurrence analysis. A saved audit rechecked all temporal trajectories; no previously detected recurrence changed. Observation counters also distinguish the historical width-dependent recursion cap from the Galloway three-attempt limit in tiny research worlds. These checks preserve the numeric trajectories.

The atlas is a buildless, local HTML/CSS/JavaScript reader of saved numbers. Optional Playwright browser checks exercise selection, reveal, palette consistency, textual inspection, nearby-world navigation, responsive layout and the complete run filter. Downloaded browser binaries and publication/source caches live outside the project and are not needed for simulation or gallery replay.

The final milestone regeneration, native replay, test output, browser checks, resource measurements and source snapshot are saved under `results/`. Scientific interpretations belong in `README.md` and `RESEARCH_RECORD.md`; this log records implementation choices only.

Chromium required execution outside the process sandbox to launch; the initial failed launch is retained with the successful retry. No new search proposals, model API calls or scientific runs were added. The resume state, command logs and resource measurements are recorded in `results/resume/checkpoint.json` and its linked verification directory. The source snapshot was refreshed after recording this audit.
